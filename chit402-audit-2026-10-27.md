## Review findings

### F1 — The public receipt shell is not signed (design/security boundary)

Reproduction:

```bash
node --input-type=module -e "const r=await (await fetch('https://api.chit402.com/receipt/chit-56e3ee6d-2acb-4cab-8fa4-dfd5f9f31e6f?format=json')).json(); console.log(JSON.stringify({unsigned:r.unsigned,issuer_signature:!!r.issuer_signature,public_attestation:!!r.public_attestation}));"
```

Observed:

```json
{"unsigned":true,"issuer_signature":false,"public_attestation":false}
```

Expected for a receipt that claims its displayed payment fields are authenticated: a signature covering at least task id, payment reference, asset, amount, payee, and the inclusion leaf. The signed tree head proves that a leaf exists in the log, but it does not, by itself, authenticate the shell's displayed fields. A consumer that treats the shell as an authenticated receipt can therefore accept fields that were not signed. The safe result is “could not check” unless an owner/JWS/public-attestation object is also verified.

Improvement: include the documented `public_attestation.jws` (or an equivalent public signature) in this shell, binding the displayed payment fields and `leaf_hash`/index to the trusted issuer key. Make the verifier fail closed when the binding is absent.

### F2 — The public proof cannot recompute the leaf from the displayed receipt

The public Merkle proof starts from a published `leaf_hash`; the receipt row hash/preimage is owner-held. The audit's mutation test changes `amount_settled` by one unit while keeping the published leaf/proof unchanged, and the proof still folds to the signed root:

```json
{"changing_unsigned_amount_keeps_tree_proof":true}
```

Expected if the proof authenticated the displayed receipt object: changing the amount would change the leaf and invalidate the root. Observed: the proof remains valid because it proves only the supplied leaf hash. This is not a tree-integrity failure; it is a missing public binding between receipt fields and the leaf.

Improvement: publish a verifiable attestation that covers the payment fields and leaf hash, or publish a canonical public leaf preimage. Keep the current proof and head checks as the log-integrity layer.

## Conclusion

The key history, signed tree head, Merkle inclusion path, Base anchor, and 2,000-atomic-unit USDC transfer all verify. The receipt payload itself is not publicly signed in the supplied URL, so the correct independent verdict is not “fully verified receipt”; it is “tree head/inclusion/payment checked, receipt payload signature unavailable.” No cosmetic issue or fabricated payment claim is reported.
